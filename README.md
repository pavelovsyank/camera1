# Запись камеры при движении

Запуск MediaMTX и Python-детектора:

```bash
docker compose up -d --build
docker compose logs -f motion-recorder
```

При движении сохраняется один ролик длительностью 15 секунд в `./recordings`
в формате MKV, с исходным видео и звуком (если он есть), без перекодирования.
Запись начинается с подключения FFmpeg после обнаружения движения; предзаписи нет.
Первый ключевой кадр камеры может прийти с задержкой. При обрыве потока ролик
может оказаться короче 15 секунд.

Во время записи новые события её не продлевают. После окончания детектор ждёт
5 секунд без движения, затем снова готов к записи. Непрерывное движение создаст
один ролик. Первые 5 секунд после подключения нужны для обучения фона.

Настройки в `docker-compose.yml`:

- `RECORD_SECONDS`: длительность ролика.
- `MOTION_MIN_AREA`: минимальная площадь движущегося объекта в пикселях
  при ширине анализируемого кадра 640. Увеличьте для уменьшения ложных срабатываний.
- `MOTION_FRAMES`: сколько кадров подряд должны содержать движение.
- `QUIET_SECONDS`: сколько ждать без движения перед повторным включением.
- `TZ`: часовой пояс имён файлов.

После изменения настроек выполните `docker compose up -d --build`.
Детектор постоянно читает поток через MediaMTX, поэтому камера остаётся подключённой
даже при `sourceOnDemand: yes`. Смена освещения и движение деревьев могут вызывать
ложные срабатывания. Автоматического удаления старых записей нет — следите за местом
на диске. Конфигурация использует `network_mode: host` для Linux.
